# Daily News 21/11/2026

### 1. Stripe evals: 14 coding agent chấm trung bình 78% nhưng chỉ 29% qua ngưỡng "đạt hoàn toàn" khi tích hợp thanh toán
- 🧪 Stripe chạy 69 kịch bản (thanh toán một lần, subscription, Connect) trên 14 cặp model + harness, có và không có Stripe agent plugin. Tác vụ gồm hosted checkout, metered billing, subscription theo seat, chia tiền marketplace
- ⚠️ Điểm trung bình 78.1% nhưng strict pass rate (đạt mọi tiêu chí bắt buộc) chỉ còn 29.4%. Stripe nhận xét agent hay nghiêng về API cũ vì xuất hiện nhiều trong dữ liệu huấn luyện, bỏ sót tính năng và bịa
- 🔌 Cả 14 agent đều điểm cao hơn khi có plugin, tăng khoảng 3–8 điểm phần trăm, số lần tìm web giảm 96%. Top theo Stripe: GPT-6 Astra 90.0% và GPT-6.1 Sol 89.6% (Codex), Opus 5.5 đạt 86.2% (Claude Code)
- 🛠️ Với dev: khi để agent viết code thanh toán, nên cài plugin chính thức và theo dõi con số strict pass thay vì điểm trung bình. Stripe đã mở mã nguồn benchmark và harness để tự chạy lại
- 🔗 [Nguồn](https://stripe.dev/blog/stripe-integration-evals-methodology)

### 4. Matt Pocock: prompt xoá sạch comment trong code vì "comment gây hại" khi làm việc với agent, hơn 2.600 like
- 💬 Prompt phân loại mỗi comment thành Tautology (lặp lại điều code đã nói), Excuse (cho agent cớ để viết cách làm tạm bợ rồi lan ra code khác), Stale (lỗi thời) và Decision Record (quyết định quan trọng, không hiển nhiên)
- 🧹 Hành động: xoá Tautology/Stale; Excuse thì xoá và mở issue sửa chỗ làm tạm; Decision Record chuyển sang ADR
- 📏 Sau đó agent tạo lint rule cấm comment theo kiểu ratchet (không cần xoá hết trong một PR), tạo skill `/delete-comment` để lặp lại, và ước tính số dòng code bớt được. Matt kết luận "comments considered harmful"
- 🔗 [Nguồn](https://x.com/mattpocockuk/status/2123798388227403983)

### 5. "Ngừng viết code thì review cũng kém đi": bài blog gây tranh luận trên Hacker News với hơn 300 điểm
- ✍️ Tác giả cekrem so sánh với nhạc công hay nhà văn: chỉ đọc và góp ý cho đầu ra do AI sinh thì kỹ năng suy luận về code sẽ mòn dần. Bài nhấn vào kỹ năng của người làm nghề chứ không bàn chất lượng code ngắn hạn
- 💬 Trên Hacker News, có người chỉ ra "best practice" đã đảo chiều: 5 năm trước lên làm quản lý bị coi là làm mòn tay nghề, nay quản lý agent lại được khuyến khích. Người khác nói nhiều người giờ gần như không review code, mất đi phần cộng tác và niềm tự hào nghề
- ⚖️ Phe ủng hộ AI đáp rằng agent giúp họ làm được việc trước đây không có thời gian, như devops, ansible, terraform, miễn là không "tắt não"
- 🧭 Gợi ý cho team: duy trì thói quen tự viết hoặc tự đọc kỹ các phần cốt lõi, nhất là khi tỉ lệ code do agent sinh ra đã cao
